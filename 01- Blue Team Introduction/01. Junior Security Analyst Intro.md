### 1. Definition
A SOC Tier 1 (L1) Analyst is the first line of defense in a Security Operations Center. Your primary job is alert triage: monitoring the SIEM (Security Information and Event Management) queue, investigating triggered alerts, filtering out False Positives (FPs), and escalating True Positives (TPs) to Tier 2 or Incident Response (IR).

### 2. Why defenders care
Tier 1 is the bottleneck of the SOC. If L1 is slow, the Mean Time to Detect (MTTD) and Mean Time to Respond (MTTR) skyrocket. Attackers rely on L1 fatigue to increase their "dwell time" (the time they spend in the network before being caught).

### 3. How it works
*   **Simple:** Telemetry (logs) from your FortiGates, Windows Servers, and endpoints flow into the SIEM. The SIEM has rules. When a rule matches a log, it creates a "ticket/alert." L1 looks at the ticket, checks if it's a real threat, and acts.
*   **Technical:** Agents (like Winlogbeat, Sysmon, or FortiGate Syslog) forward data to a log shipper (Logstash/Fluentd), which parses and normalizes the data into a common schema (like ECS - Elastic Common Schema) before indexing it in the SIEM backend (Elasticsearch, Splunk, Sentinel). Correlation rules (written in SPL, KQL, or Sigma) run continuously against the stream. When an alert fires, L1 uses SOAR (Security Orchestration, Automation, and Response) playbooks to gather contextual artifacts (IPs, Hashes, Domains) before deciding on a verdict.

### 4. Key terms
*   **True Positive (TP):** A legitimate security alert (e.g., actual malware).
*   **False Positive (FP):** Benign activity that triggered a security rule (e.g., an admin running a PowerShell script that looks like malware).
*   **Dwell Time:** The duration an attacker remains undetected in the environment.
*   **SLA (Service Level Agreement):** The mandated time limit to triage an alert (e.g., "Critical alerts must be triaged within 15 minutes").
*   **Playbook/Runbook:** Standardized steps for an analyst to follow when investigating a specific alert type.

### 5. Attacker view + MITRE ATT&CK IDs
Attackers know Tier 1 analysts are overwhelmed. They abuse **Alert Fatigue** by generating massive amounts of low-level noise (port scanning, brute-forcing) to hide their real payload. They also use **Living off the Land (LoL)** binaries to blend in with normal admin activity.
*   **Defense Evasion (T1070 - Indicator Removal):** Clearing event logs to blind Tier 1.
*   **Execution (T1059.001 - PowerShell):** Using native tools so Tier 1 assumes it's normal IT admin work.
*   **Resource Development (T1583 - Acquire Infrastructure):** Using residential proxies so Tier 1 sees C2 traffic as "normal web browsing."

### 6. Defender view: logs, Event IDs, detection, response
Since you know AD and Windows, here is what Tier 1 actually looks at:
*   **Windows Security Logs:** 
    *   `4624` / `4625` (Logon Success/Failure) - Crucial for spotting brute force.
    *   `4688` (Process Creation) - Needs command-line auditing enabled via GPO to be useful.
*   **Sysmon (System Monitor):** The holy grail for Windows visibility.
    *   `Event ID 1`: Process Creation (shows parent/child lineage).
    *   `Event ID 3`: Network Connection (shows what process talked to the internet).
    *   `Event ID 11`: File Creation (dropped payloads).
*   **Detection:** `winword.exe` (Parent) spawning `cmd.exe` or `powershell.exe` (Child).
*   **Response:** Isolate host via EDR (CrowdStrike/Defender), disable the compromised AD user account, push a block rule to the FortiGate for the C2 IP.

### 7. Mini scenario (attack > detect > respond)
*   **Attack:** Finance user opens a phishing invoice. The macro runs, downloading a Cobalt Strike beacon.
*   **Detect:** SIEM alerts on "Suspicious Process Lineage". L1 opens the ticket and sees `winword.exe` spawned `powershell.exe` with a base64 encoded command. L1 decodes the command and sees an outbound connection to a strange IP.
*   **Respond:** L1 checks the IP in VirusTotal/AbuseIPDB (it's flagged as malicious). L1 follows the Phishing Playbook: isolates the laptop via EDR, resets the user's AD password, and emails the SOC Engineer to block the IP on the perimeter FortiGate. Ticket escalated to Tier 2 for full DFIR (Digital Forensics and Incident Response).

### 8. Sigma/SPL/KQL sample
**Scenario:** Detecting Word spawning PowerShell.

*Splunk SPL:*
```splunk
index=sysmon EventCode=1 
| search ParentImage="*winword.exe" Image="*powershell.exe"
```

*Microsoft Sentinel KQL:*
```kusto
DeviceProcessEvents
| where InitiatingProcessFileName =~ "winword.exe" 
| where FileName =~ "powershell.exe"
```

*Sigma Rule (Vendor Agnostic):*
```yaml
title: Suspicious Word Spawning PowerShell
logsource:
    category: process_creation
    product: windows
detection:
    selection:
        ParentImage|endswith: '\winword.exe'
        Image|endswith: '\powershell.exe'
    condition: selection
level: high
```

### 9. Free tools
*   **CyberChef:** For decoding base64, hex, or ROT13 payloads found in logs.
*   **VirusTotal / AbuseIPDB / Urlscan.io:** For checking reputation of IOCs (Indicators of Compromise).
*   **Any.Run / Hybrid Analysis:** Interactive malware sandboxes to see what a suspicious file actually does.
*   **SWIMLANES.io:** For drawing out attack paths when escalating to Tier 2.

### 10. Lab idea
*   **LetsDefend.io:** Excellent for pure Tier 1 SOC simulation. You get a fake SIEM dashboard and have to close tickets.
*   **TryHackMe:** "SOC Level 1" Learning Path (Specifically the "Investigating with Splunk" and "Investigating with ELK" rooms).
*   **Boss of the SOC (BOTS):** Splunk releases free, massive datasets of real captured attacks. Great for practicing SPL queries.

### 11. Common mistakes
*   **Alert Fatigue / "Close-itis":** Seeing 50 identical alerts and closing the 50th one without actually checking the logs.
*   **Trusting the Ticket:** Relying solely on the SIEM's automated summary instead of looking at the raw event logs.
*   **Poor Escalation Notes:** Handing a ticket to Tier 2 and just saying "Looks bad." (Always include: What happened, what you checked, and why you think it's a True Positive).

### 12. 5-bullet recap
1.  Tier 1 is the triage engine of the SOC, focused on speed and accuracy to minimize attacker dwell time.
2.  Attackers use LoL binaries and alert fatigue to slip past Tier 1 (MITRE T1059, T1070).
3.  Process lineage (Parent/Child relationships) via Sysmon Event ID 1 is your best friend for spotting malicious execution.
4.  Always decode suspicious command lines (using CyberChef) before declaring an alert a False Positive.
5.  Quality escalation notes are just as important as the investigation itself.
