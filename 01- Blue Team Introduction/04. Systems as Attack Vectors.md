# Systems as Attack Vectors (TryHackMe SOC L1)

## 1. Definition
- System = server, endpoint, cloud (M365), network appliance (FortiGate, VPN). Hosts data and services.
- Attacker hits system directly, bypassing the user.
- Impact: phish one mailbox = one account. Breach mail server = all mailboxes.

| Breached System | Attack Value |
|---|---|
| Student laptop | Steal Steam account, add to botnet |
| Bank IT admin laptop | Access to internal banking systems |
| Law firm mail server | Dump mailboxes, blackmail |
| Industrial network server | Ransomware across whole network |
| Gov website panel | Defacement / activism |

## 2. Why Defenders Care
- Exploitation needs zero user interaction.
- One unpatched edge device (FortiGate, Exchange, ESXi) = silent entry to internal network.
- Patch management = main bottleneck.

## 3. Attack Vectors on Systems
**Human-led**
- Unknown USB, pirated software, weak/reused passwords.
- 81% of breaches involve stolen/breached passwords.

**Vulnerabilities**
- 2024: 40,000+ CVEs published, 300+ actively exploited.
- Flaw in memory management or input validation (buffer overflow, deserialization) → RCE.

**Supply Chain**
- Attacker breaches vendor or library, pushes legit-looking update to all users.
- Examples: SolarWinds, 3CX, Lottie Player (TryHackMe itself was hit).
- EDR and firewall allow it: trusted source.

**Misconfiguration** (not a bug, a setup mistake)
- Examples: password "123456" or "1111", default creds, open cloud resource.

## 4. Patching Race
1. **Zero-day**: vendor unaware, no patch, attacker exploiting. Defender: mitigations, WAF/IPS, monitoring.
2. **Disclosure + CVE**: flaw public. PoC appears. Mass scanning (Shodan/Masscan).
3. **Patch released**: attackers reverse-engineer patch, build weaponized exploit.
4. **N-Day**: any known vuln where target still unpatched.
- Attackers prefer N-Day (cheaper than zero-day).

## 6. Vulnerability vs Misconfiguration
| | Vulnerability | Misconfiguration |
|---|---|---|
| Cause | Bug in software | Mistake in setup |
| Fix | Vendor patch | Reconfigure / hardening |
| Responsible | Vendor + patch team | IT / admin |
| Example | Shellshock, Log4Shell | "123456", open AWS resource |
| SOC detection | IPS signature, vuln scan, KEV match | Config audit, pentest, default-creds scan |

## 7. Real-World Cases
- **SolarWinds**: poisoned update reached thousands of companies. Lesson: trusted vendor ≠ safe.
- **3CX**: supply chain, trojanized desktop app. Lesson: watch outbound connections from known apps.
- **Shellshock**: Bash bug in Linux, present since 1992, found 2014. Lesson: vulns can hide for years.
- **McDonald's "123456"**: 64M job applications exposed via weak default password. Lesson: password policy, no default creds.
- **AWS bank breach**: 106M customers, cloud misconfig. Lesson: audit cloud config.
- **Smart fridge botnet**: misconfigured IoT turned into botnet. Lesson: IoT inventory and segmentation.
- **Lottie Player**: animation library used by TryHackMe compromised. Lesson: monitor third-party dependencies.

## 9. Defender View
**Log sources**
- Perimeter: FortiGate IPS/WAF, proxy, DNS.
- Server: IIS/Apache/Nginx logs, Windows Event Logs, Exchange/SQL.
- Endpoint: EDR, Sysmon (Event ID 1 process creation, Event ID 3 network connection).

**Detection signals**
- Scanning: many HTTP 404/500 from one IP, IPS signatures firing.
- **Golden rule**: web server process spawns shell. `w3wp.exe`, `httpd.exe`, `tomcat.exe`, `java.exe` → `cmd.exe`, `powershell.exe`, `whoami.exe`.
- Supply chain: isolated service or trusted app suddenly makes outbound connection to unknown IP (C2 beaconing).

## 10. Response Playbook
**Zero-day announced**
- Restrict access to trusted IPs only.
- Apply vendor workaround.
- Block attack patterns on IPS/WAF.
- Monitor for exploitation traces until patch ships.

**CVE patch released**
- Check CISA KEV: if exploited, drop everything.
- Patch by priority (internet-facing first).
- **Hunt after patching**: patch does not evict an attacker already inside.

**Misconfiguration found**
- Fix config now (change default creds, close exposure).
- Config audit (CIS benchmarks).
- Vuln scan other systems. Assume someone already abused it.

**Supply chain suspected**
- Isolate hosts that received the update.
- Block C2 IPs/domains.
- Identify infected version, roll back.
- Rotate credentials, contact vendor.
- Hunt for lateral movement.

## 11. Mini Scenario
- **Attack**: attacker finds unpatched FortiGate SSL-VPN with N-Day, sends crafted HTTP request to run OS commands.
- **Detect**: FortiGate IPS alert. Minutes later, Sysmon shows new SSH connection from FortiGate's internal IP.
- **Respond**: L1 blocks SSL-VPN portal via Local-In-Policy. L2 patches FortiOS, audits for backdoor accounts, resets admin passwords.

## 12. Detection Samples
**Sigma: web server spawning shell**
```yaml
title: Suspicious Web Server Spawning Shell
logsource:
    category: process_creation
    product: windows
detection:
    selection:
        ParentImage|endswith:
            - '\w3wp.exe'
            - '\httpd.exe'
            - '\tomcat.exe'
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\sh.exe'
    condition: selection
level: critical
```

**KQL**: in Defender XDR advanced hunting, replace `TimeGenerated` with `Timestamp`.
```kusto
DeviceProcessEvents
| where InitiatingProcessFileName in~ ("w3wp.exe","httpd.exe","nginx.exe","java.exe","tomcat.exe","php-cgi.exe")
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","bash","sh","whoami.exe","certutil.exe")
| project TimeGenerated, DeviceName, InitiatingProcessFileName, FileName, ProcessCommandLine
```

## 13. Common Mistakes
- **Patch lag**: fear of breaking production. 30 days delay = 30 days guaranteed attacker access.
- **Patching without hunting**: backdoor survives patch.
- **Ignoring edge devices**: FortiGate, VPN, UPS, HVAC controllers.
- **Ignoring third-party code**: blind trust in vendor updates.
- **Over-reliance on IPS**: signatures bypassed via obfuscation/fragmentation.
- **CVSS alone**: 7.5 CVE with working GitHub exploit beats theoretical 9.8. Use KEV for priority.

## 15. Lab Ideas
1. **Exploit + Detect**: Metasploitable2 or Windows Server 2008 behind FortiGate/pfSense VM. Exploit with Metasploit (MS17-010). Analyze IPS logs + Sysmon on victim.
2. **Virtual Patching**: DVWA or old WordPress. Find vuln with Nuclei, write Snort/Suricata rule to block payload without patching.

## 16. Quick Revision
- System breach impact >> user breach.
- 81% of breaches tied to passwords.
- Zero-day = vendor unaware, no patch.
- N-Day = known, target unpatched. Attackers prefer it.
- Patch answers a CVE. Misconfig fixed by better setup.
- Virtual patching = IPS/WAF before real patch.
- Supply chain = trust in vendor/library turned into weapon.
- Golden rule: web server → shell = breach.
- C2 beaconing from isolated service = red flag.
- KEV > CVSS for priority.
- Patch then hunt, not patch only.
- Edge devices = main ransomware entry points.
- Misconfig examples: McDonald's "123456", AWS 106M, smart fridges.
- SOC often finds misconfig only after exploitation.
- Proactive: pentest + vuln scans + CIS config audit.
