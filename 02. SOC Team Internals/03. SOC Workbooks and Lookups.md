# SOC Workbooks and Lookups (TryHackMe): Study Notes

## 1. Big Picture
- Alerts show IPs, usernames, and hostnames. Alone they mean nothing.
- **Lookups** (identity inventory, asset inventory, network diagram) give context: who, what, where.
- **Workbooks** give fixed steps, so no analysis step is skipped and no verdict is made without evidence.
- L1 analysts are junior. Workbooks written by seniors protect them from mistakes.

---

## 2. Assets & Identities

### Identity inventory
- Catalogue of employees (user accounts) and services (machine accounts), with privileges, contacts, and roles.
- Example fields: Full Name, Username, Email, Role, Location, Access.
- Example rows from the room:
  - G.Baker: Chief Financial Officer, Europe/UK, access VPN, HQ, FINANCE.
  - R.Lund: US Financial Adviser, US/Texas, access VPN, FINANCE.
  - svc-veeam-06: Backup Service Account, access VEEAM, DMZ, HQ.

| Source | Examples | Note |
|---|---|---|
| Active Directory | On-prem AD, Entra ID | AD is an identity database, commonly used by SOC |
| SSO providers | Okta, Google Workspace | Cloud alternative to AD |
| HR systems | BambooHR, SAP, HiBob | Employees only, but full employee data |
| Custom solution | CSV / Excel | Common when IT/security keep their own |

### Asset inventory (asset lookup)
- List of all computing resources in the IT environment.
- "Asset" is vague. This room covers **servers and workstations only**.
- Example fields: Hostname, Location, IP Address, OS, Owner, Purpose.
- Example rows from the room:
  - HQ-FINFS-02: UK Datacenter, 172.16.15.89, Windows Server 2022, Central IT, file server for financial records.
  - HQ-ADDC-01: primary AD domain controller.
  - L007694: remote MacOS 13 laptop, owner A.Kelly (DevOps).

| Source | Examples | Note |
|---|---|---|
| Active Directory | On-prem AD, Entra ID | Also a solid asset database |
| SIEM or EDR | Elastic, CrowdStrike | Agents collect info on monitored hosts |
| MDM solution | MS Intune, Jamf MDM | Built to list and manage assets |
| Custom solution | CSV / Excel | Same as identity inventory |

### Scenario: G.Baker / HQ-FINFS-02 / R.Lund
Alert: G.Baker logged into HQ-FINFS-02, downloaded "Financial Report US 2024.xlsx", shared it with R.Lund.

| Question | Answered by |
|---|---|
| Who is G.Baker? Working hours and role? | Identity inventory |
| What is HQ-FINFS-02's purpose and location? | Asset inventory |
| Who can access HQ-FINFS-02? | Identity inventory (Access field) plus asset owner |
| Why would R.Lund need financial records? | Identity inventory (role, access) |

### Identity vs Asset

| | Identity inventory | Asset inventory |
|---|---|---|
| Describes | Users and service accounts | Servers and workstations |
| Key fields | Role, access, location, contact | Hostname, IP, OS, owner, purpose |
| Answers | "Who is this? Is this normal for them?" | "What is this host? What does it do?" |
| Sources | AD, SSO, HR, custom | AD, SIEM/EDR, MDM, custom |

## 3. Network Diagrams

- A visual schema of locations, subnets, and their connections.
- SOC uses it to understand suspicious network activity, especially in bigger companies.
- It gives meaning to IPs seen in firewall logs.

### Firewall log scenario
1. 08:00: IP 103.61.240.174 repeatedly connects to the corporate firewall on TCP/10443.
2. 08:23: Firewall shows that IP translated to internal 10.10.0.53.
3. 08:25: 10.10.0.53 scans 172.16.15.0/24, finds no open ports.
4. 08:32: Same IP scans 172.16.23.0/24. Attack seems ongoing.

### Questions and what answers them

| Question | Answer from diagram |
|---|---|
| What runs on port 10443, why connect there? | It is the VPN (attacker targeted vpn.tryhatme.thm) |
| Which subnet is 10.10.0.53 in? | VPN Subnet |
| Why would it touch other subnets? | It should not. Scanning other subnets is abnormal |

### Reconstructed attack path
1. Threat actor performed **VPN brute force** on vpn.tryhatme.thm.
2. After successful brute force and VPN login, actor got an IP from the **VPN Subnet**.
3. Actor scanned the **Database Subnet**, likely blocked by firewall rules.
4. No success, so actor switched to the **Office Subnet** to find the next target.

## 4. SOC Workbooks

- Also called **playbook, runbook, workflow**.
- Structured document defining the steps to investigate and remediate a specific threat, efficiently and consistently.
- **Why seniors write them:** L1 are junior and not expected to triage every attack perfectly.
- **Why L1 follow them:** recommended, sometimes required. Avoids mistakes, streamlines analysis, prevents verdicts without enough evidence.
- Most workbook diagrams come with a detailed text guide and links to resources.

### 3 logical groups

| Group | What it does |
|---|---|
| Enrichment | Use Threat Intelligence and identity inventory to learn about the affected user |
| Investigation | Use gathered data and SIEM logs to decide if the login is expected |
| Escalation | Escalate to L2, or communicate the login with the user if necessary |

### Unusual Login Location workbook
- Aimed at alerts about atypical email, web, or corporate VPN logins.
- Divided into the 3 groups above. Follow steps in the correct order.
- Diagram not included in text. Exact steps not covered here.

### Template [Extra]
```
[Workbook: <alert type>]
Trigger: <which alert/rule>
Goal: <what verdict is needed>

ENRICHMENT
- [ ] Lookup user in identity inventory (role, location, access)
- [ ] Lookup host in asset inventory (owner, purpose)
- [ ] Check IP/domain in Threat Intelligence
- [ ] Network diagram: which subnet, expected path?

INVESTIGATION
- [ ] SIEM: related events for user/host/IP
- [ ] Is activity expected for this role/time/location?
- [ ] Verdict: TP / FP + Why

ESCALATION
- [ ] Escalate to L2 if: <conditions>
- [ ] Contact user by <phone / other channel> if needed
- [ ] Write alert report (5Ws)
```

## 7. Common Mistakes

| Mistake | Fix |
|---|---|
| Judging an alert from the username/IP alone | Look up identity and asset first |
| Mixing identity and asset inventory | Identity = who. Asset = what host |
| Skipping workbook steps | Follow in order: Enrichment, Investigation, Escalation |
| Verdict before enrichment | Gather context first, then decide |
| Ignoring network context | Check which subnet, and whether the traffic path makes sense |
| Treating a quiet scan as harmless | Scans from a VPN IP across subnets are suspicious (see 08:25 / 08:32 scenario) |
| Trusting only one inventory source | Sources can be partial (HR = employees only). Cross-check |

## 8. Practice: 3 Mini Scenarios

### A. CFO file share
Alert: G.Baker logs into HQ-FINFS-02, downloads a financial report, shares it with R.Lund.
- **Enrichment:** identity inventory: G.Baker is CFO, has FINANCE access. R.Lund is US Financial Adviser, has FINANCE access. Asset inventory: HQ-FINFS-02 is the financial file server, owned by Central IT.
- **Investigation:** SIEM logs: login time and source vs G.Baker's normal working hours and location. Check the sharing method.
- **Escalation:** if timing or source is unusual, contact G.Baker by phone or escalate to L2.
- **Verdict:** likely expected (right roles, right server) if timing and source are normal. Document in the report.

### B. VPN brute force and scanning
Alert chain: external IP 203.0.113.74 hammers the firewall on TCP/10443. Later an internal 10.10.0.53 scans 172.16.15.0/24, then 172.16.23.0/24.
- **Enrichment:** network diagram: 10443 is the VPN, 10.10.0.53 is in the VPN Subnet. TI lookup on 203.0.113.74.
- **Investigation:** SIEM/firewall logs: repeated failures, then a success, then scans from the assigned VPN IP. A VPN user has no reason to scan other subnets.
- **Escalation:** escalate to L2. Likely compromised VPN account. Remediation (reset credentials, block access) is needed.
- **Verdict:** True Positive.

### C. Unusual login location
Alert: K.Danner (CTO, Europe/UK) logs into email from a country outside his normal location.
- **Enrichment:** identity inventory: role and location (UK). TI lookup on the source IP.
- **Investigation:** SIEM: other logins for this user, device, time. Is travel plausible? Any follow-up actions after login?
- **Escalation:** contact the user through another channel (phone) to confirm. Escalate to L2 if not confirmed or if suspicious actions follow.
- **Verdict:** depends on user confirmation. Confirmed travel = expected. Denied = True Positive, escalate.

## 9. Quick Revision Notes
- Alerts need context. Lookups provide it.
- Identity inventory = users + service accounts, with role, access, location, contact.
- Asset inventory = servers + workstations, with owner, purpose, IP, OS.
- Identity sources: AD, SSO (Okta, Google Workspace), HR (BambooHR, SAP, HiBob), custom CSV.
- Asset sources: AD, SIEM/EDR, MDM (Intune, Jamf), custom CSV.
- Network diagram = locations, subnets, connections. Explains IPs, ports, and attack paths.
- Attack path example: VPN brute force → VPN Subnet → Database Subnet (blocked) → Office Subnet.
- Workbook = playbook = runbook = workflow.
- Seniors write workbooks to support L1. L1 should follow them.
- 3 groups: Enrichment → Investigation → Escalation.
- Enrichment: Threat Intel + identity inventory.
- Investigation: gathered data + SIEM logs, decide if expected.
- Escalation: L2 or contact the user.
- Following the steps in order prevents verdicts without evidence.
- Push your team to build and maintain workbooks.

## 11. Practical Tips [Extra]
All items below are my own advice, not room content.

- Keep a bookmarked list of where your identity inventory, asset inventory, and network diagram live. Find them before the night shift, not during.
- Put lookup results in the alert report under Who and Where.
- If a lookup has no match (unknown host, unknown user), treat that as a finding and note it.
- When inventories disagree (HR vs AD), say so in the report and ask L2.
- Your FortiGate and AD background helps: you can read firewall NAT logs and subnet layouts fast.
